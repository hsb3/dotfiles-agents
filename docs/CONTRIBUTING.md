# Contributing

*Status: active — extender-development SOP + the D6 entry-gate contract, in-repo. See the
note at the bottom on what this document is grounded in.*

This repo is a Claude Code marketplace: a curated set of coding-agent extenders
(`primitives-core/skills/`, `agents/`, `hooks/`) assembled into plugin bundles
(`project-workflow`, `repo-standards`) that install via `claude plugin marketplace add
hsb3/dotfiles-agents`. Contributing here means adding, changing, or retiring a primitive.

## Where you work

- **Edit primitives under `primitives-core/` only.** `plugins/` and
  `.claude-plugin/marketplace.json` are generated by `scripts/gen_marketplace.py` — never
  hand-edit them. Change the source, then `make build`.
- **`primitives-core.yaml` is the manifest of record.** A primitive isn't real until it has a
  roster entry — see [`primitives-core/README.md`](../primitives-core/README.md) for the
  entry schema (`id · type · source · shelf · origin · disposition · targets · plugins ·
  requires`).
- **`primitives-core/` is self-authored only.** Third-party extenders never get copied in —
  they're recorded by reference in `externals.yaml` (upstream URL + pinned ref) and pulled at
  build time. Never pass a third party's bundle along wholesale; compose bundles from
  third-party + authored primitives.
- Every generated artifact ships with a deterministic regenerator and a `--check` drift mode
  (`make build` / `make build-check`) — add new generated artifacts the same way.

## Branch and PR governance

`dev` is the integration branch; `main` is publish-only (ADR
[0007](decisions/0007-distribution-restructure-dev-main.md)):

- Branch off `dev`, open your PR **into `dev`**.
- **Never commit or merge to `main`.** It's the CI-published marketplace surface — advanced
  only by the sanctioned `dev` → `main` promotion, never by a direct push.
- Keep changes surgical and scoped to one slice; match the repo's existing style.

## The task interface

`make ci` is canonical (`make help` lists every target). It runs:

- `check` — roster ↔ disk drift guard (schema + provenance).
- `build-check` — marketplace regen drift guard (`plugins/` + `marketplace.json` match
  source).
- `test` — the stdlib-only unit tests (`python3 -m unittest`; zero-install is an invariant).

A PR that doesn't pass `make ci` locally won't pass it in CI either — run it before you push.

## The entry gate

Every PR into `dev` clears two tiers before it can merge. This is the D6 deliverable's
contract, captured as of this writing (see the grounding note below) — it will graduate to
its own enforced CI lanes as D6 lands; until then, treat it as the review bar a human or
agent reviewer applies by hand.

**Tier 1 — machine floor** (required CI on every PR; a red floor is not mergeable):

1. **Identity-neutrality** — no name, org, repo, or issue hardcoded into any shipped
   artifact; personalization only through data surfaces.
2. **Tests pass** — the extender's real behavior is exercised, not just its shape.
3. **Provenance / externals conformance** — no third-party copies in `primitives-core`;
   every `externals.yaml` entry carries non-null recorded intent (upstream + ref) or is
   dropped with a note.
4. **Hook-layout** — hooks use the ratified hook-dir layout, `hooks/<name>/hook.py` (config +
   event-named script; never inline bash in `settings.json` — ADR
   [0002](decisions/0002-hooks-as-script-plus-config.md)).

**Tier 2 — judgment review** (a reviewer attests on the PR; no separate promotion step):

- **Belongs** — fits the current bundle lineup, not a speculative addition.
- **Quality** — the primitive does what its `SKILL.md`/description claims.
- **Non-duplicative** — doesn't re-implement what another shipped primitive already covers.
- **Use-case pull** — motivated by a real, named use, not built ahead of need.

Passing both tiers *is* graduation — there's no separate incubation or promotion workflow in
this repo.
