## Body

## What

Package the three BuilderIO visual-planning skills — **`visual-plan`**,
**`visual-recap`**, **`visualize-repo`** — as a distributable dotfiles-agents
plugin bundle (a cross-desk standalone), so any repo can enable them via
`claude plugin enable` instead of copying `.claude/skills/` files per-repo.

## Why

They currently live committed per-repo — source of truth is
`hsb3/agent-native-sandbox` `.claude/skills/{visual-plan,visual-recap,visualize-repo}/`.
Each new repo needs a manual `npx @agent-native/skills add … --scope project`
install (procedure in that repo's `_meta/reference/skills-setup.md`). Onboarding
them to the marketplace gives the standard deny-by-default + per-project
`claude plugin enable` path and one canonical copy to maintain instead of N repo copies.

## Composition — what's Henry's vs upstream

- **Upstream (BuilderIO):** the skill bodies + `references/*.md` (canvas,
  wireframe, document-quality, exemplar, connection, local-files). Installed via
  `npx @agent-native/skills@latest add`.
- **Henry's override:** only the `## Installed Mode` preamble in each `SKILL.md`.
  It points the workflow at the **local Plan app container**
  `ghcr.io/hsb3/plan-app` (private) instead of the unreliable hosted bridge, and
  is now **machine-portable** — GHCR login derived from the GitHub session, the
  Anthropic key optional + env-driven, rendering/editing need no secrets. See
  agent-native-sandbox commit `caeb176`.

## Deliverables

- A plugin bundle (proposed name `visual-planning`; `plan-app` also a candidate)
  under the dotfiles-agents marketplace, containing the 3 skills + their `references/`.
- The portable `Installed Mode` preamble carried as the canonical override.
- A **re-sync procedure**: re-pull an upstream BuilderIO skill update and
  re-apply the preamble overlay without losing it — the maintenance crux, since
  the bodies are upstream and only the preamble is ours.
- Marketplace registration + a plugin README (per the #144 README-coverage convention).
- A migration note: what supersedes the per-repo `skills-setup.md` install for
  Henry's own repos, and the tradeoff kept (per-repo committed = travels with the
  repo for collaborators who clone; plugin = user/machine-scoped).

## Acceptance criteria

- `claude plugin enable visual-planning@dotfiles-agents` in a fresh repo surfaces
  `/visual-plan`, `/visual-recap`, `/visualize-repo`.
- Running one authors a plan that renders in the container on any Apple-Silicon
  machine logged into GitHub (the portability contract from the source repo), with
  no per-machine secret tooling.
- The re-sync procedure is documented and demonstrated once (an upstream update
  pulled, preamble preserved).

## Open questions

- **Placement** — standalone cross-desk plugin (per the #134 desk-set restructure
  vocabulary) vs attached to a desk. These are cross-cutting, not desk-specific →
  lean standalone.
- **Private-image coupling** — the bundle is not self-contained: it depends on the
  private `ghcr.io/hsb3/plan-app` + GHCR read access. Acceptable for a personal
  marketplace; document the prerequisite. (Image stays private; the owner flips it
  to public manually when proven — do not surface publishing as a task.)
- **Upstream drift** — cadence for re-pulling BuilderIO skill updates, and whether
  to pin a known-good upstream skills version.
