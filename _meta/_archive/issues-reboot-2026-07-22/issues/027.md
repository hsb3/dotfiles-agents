## Problem

`project-workflow` bundles 9 skills + 1 agent (`primitives-core.yaml`, `plugins: [project-workflow]`)
with no shared naming convention — unlike every other multi-skill toggle plugin in the roster
(`langchain-stack`: `langchain-*`/`langgraph-*`/`langsmith-*`; `obsidian-plugin-dev`: `obsidian-*`;
`deep-agents`: `deep-agents-*`), which all prefix per `manifests/naming.md`'s own pattern
(`<domain>-<capability>` for skills, `<domain>-<role>` for agents). project-workflow's members read
as unrelated names: `comms`, `diagrams`, `handoff`, `agent-dot-md-authoring`,
`readme-value-and-proof`, `board-reporting`, `board-triage`, `github-project-board`,
`planning-desk`, plus the `board-analyst` agent.

It also has no cohesion layer. The plugin covers two families that compose into one
solo-project workflow — **ops** (`github-project-board`, `board-triage`, `board-reporting`,
`board-analyst`, `planning-desk`, `handoff`) and **output** (`comms`, `diagrams`,
`agent-dot-md-authoring`, `readme-value-and-proof`) — but nothing in the plugin teaches that
composition or routes between the 10 members. `plugin.json`'s description
(`plugins.yaml`, id: `project-workflow`) already gestures at both halves but doesn't name the
output family's skills explicitly.

Separately: there is no mechanism today for a plugin to ship its own README.
`scripts/translate.py`'s plugin-assembly loop (~L378-420) writes `.claude-plugin/plugin.json`
from `plugins.yaml` + roster membership only; no generated plugin under
`targets/claude-code/plugins/` carries a README.
