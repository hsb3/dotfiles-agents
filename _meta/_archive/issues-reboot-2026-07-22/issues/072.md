## Body

Found on the fleet-dashboard test bed (2026-07-03): after running the desk toolkit, a routine `git add -A` committed `_meta/plans/_utils/__pycache__/_repo.cpython-313.pyc` (fleet-dashboard `56ba72b`, fixed in the follow-up commit).

## Problem

The desk-tracking pattern `!_meta/plans/` + `!_meta/plans/**` re-includes EVERYTHING under the desk — including Python bytecode the `_utils/` scripts generate on first run. dotfiles-agents itself is protected only by its own trailing `__pycache__/` block (`.gitignore:42-44`, placed after the negation precisely for this), but:

- the repo-meta-structure `assets/gitignore.template` carries the negation pattern with no `__pycache__` guard;
- the planning-desk skill's setup mode (step 2, gitignore wiring) doesn't mention it;
- non-Python repos (fleet-dashboard is Node) have no reason to carry a global Python block, so the bytecode lands tracked on the first `git add -A` after any toolkit run.

## Deliverables

- `assets/gitignore.template`: add `_meta/plans/_utils/__pycache__/` (or a scoped `_meta/plans/**/__pycache__/`) AFTER the plans negations, with the last-match-wins comment.
- planning-desk SKILL.md setup step 2: mention the guard when wiring the negation.
- Optional: IGNORE checklist row asserting `gitignore-ignores: _meta/plans/_utils/__pycache__/probe.pyc` so the audit catches it.

## Acceptance criteria

- Fresh desk setup per the template followed by a toolkit run leaves `git status` clean (no pyc); test or documented proof.
- `make ci` green; targets regenerated.

## Dependencies & gates

- `make ci` + targets drift guard fire (skill asset edits).
