## Body

Two more Gate-2 pilot findings (raptorgpt-agents PR #541 review pass, 2026-07-02) — template defects in the repo-meta-structure standard's assets, surfaced only when the scaffold ran against a repo with its own conventions:

1. **Issue templates hardcode label names.** The feature template applies `enhancement`; the pilot repo's taxonomy uses `feature` (fixed in-PR there). The epic template references an `epic` label that may not exist in the target repo at all. The templates assume a label taxonomy the scaffold neither creates nor verifies (labels are declared in `_meta/mise-en-place.yml` for github-project-board, never provisioned).
2. **Duplicate-reviewer blind spot.** The audit's GH-08 checks for `.github/workflows/claude-review.yml` by filename; the pilot repo already had an equivalent review workflow under a different name ("PR Review with Progress Tracking"), so the scaffold added a second reviewer — two AI reviews and double token spend per push until deduped by hand. Also: the pilot's pre-existing workflow had a concurrency/cancel-stale setting worth adopting in the standard's template.

## Deliverables
- Templates: either derive labels from the manifest's `gh_issue_labels` (with a documented default set) or ship label-less templates; document the constraint in the standard.
- Audit/scaffold: content-probe for existing claude-review-equivalent workflows (e.g. grep for the action name across `.github/workflows/`) and report a CONFLICT/MANUAL instead of creating a duplicate.
- Consider `concurrency` + cancel-in-progress in the claude-review template.

## Acceptance criteria
- Re-running the pilot sequence on raptorgpt-agents (post-#541) plans zero duplicate workflows and no unknown-label templates; `make ci` green.

Refs: raptorgpt-agents#541 (commit 5), raptorgpt-agents#542 (repo-side label reconcile); sibling finding #38 (gitignore-swallow).
