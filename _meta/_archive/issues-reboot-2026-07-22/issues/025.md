## Body

> **Origin:** surfaced by the #22 test suite. `translate.py` reads files with `open(...).read()` and never closes them; the new tests raise `ResourceWarning`s (currently silenced in the runner via `-W ignore::ResourceWarning`).

## Problem

`scripts/translate.py` opens files without closing them in several hot paths -- e.g. the parsers (`:56`, `:109`), `sha256_path` (`:185`), `skill_display_title` (`:226`), and others use `open(path).read()` / `for raw in open(path)`. Under the unit tests this surfaces as `ResourceWarning: unclosed file`, which `make test` currently hides with `-W ignore::ResourceWarning`. The leak is benign in the short-lived CLI but is a latent correctness/style issue and forces the test runner to suppress a whole warning class.

## Deliverables

- A -- wrap every read in `translate.py` in a `with` block (or a small `read_text(path)` / `read_bytes(path)` helper) so no handle leaks.
- B -- drop the `-W ignore::ResourceWarning` suppression from the `make test` target once the leaks are gone.

#### Minimal fix shape

Two repeated patterns cover 13 of the 15 sites, so a pair of tiny helpers near the top of the file removes the duplication cleanly:

```python
def read_text(path):
    with open(path, encoding="utf-8") as fh:
        return fh.read()

def read_bytes(path):
    with open(path, "rb") as fh:
        return fh.read()
```

- Sites 8–10 (`.read()` with `encoding="utf-8"`) → `read_text(path)`.
- Sites 6, 7, 13 (`"rb"` + `.read()`) → `read_bytes(path)`.
- Site 11 (`json.load(open(...))`) → `json.loads(read_text(path))`, or a `with` block if `json.load(fh)` is preferred.
- Sites 14, 15 (`json.load(open(...))` guarded by `os.path.exists`) → same as above.
- Sites 1–5 (`for raw in open(path, ...):`) iterate line-by-line, so they don't fit `read_text` as cleanly — wrap each in `with open(path, encoding="utf-8") as fh: for raw in fh:` (keeping the existing loop body indented one level deeper), rather than forcing them through the helper.
- Site 12 (a single write-then-immediately-read-elsewhere) → `with open(..., "w") as fh: fh.write(...)`.

This is a pure resource-handling refactor — no output/behavior change, so `targets/` stays byte-identical and `make ci`'s drift guard stays green.
