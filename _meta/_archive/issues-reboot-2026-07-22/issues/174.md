## Decision record + delivery (closes via PR #177)

Owner decisions (2026-07-21, this session) on the data-shape report's §5 open questions:

1. **Retention: keep everything durably.** All four collections (`runs`, `run_events`, `tool_calls`, `artifacts`) live in the extender-db PocketBase with no aging-out. `system/thinking_tokens` counter events are dropped at ingest (running-counter noise, ~17% of rows); the raw `.log` files remain on disk unchanged, so nothing is unrecoverable.
2. **Blobs: PB `file` field.** `artifacts.blob` is a PocketBase file field — and to honor the "self-contained, clone-survivable" intent, `evals/pb_data/storage/` is now tracked in git alongside `data.db` (`.gitignore` negation; ~20 MB projected at 100 campaigns).
3. **Dedup.** Canonical mirrors: claude `message.content[].content` (the `tool_use_result.*` mirror leaves are replaced with `{"$deduped": "content"}` markers); opencode `metadata.diff` (`metadata.filediff.patch` replaced with a marker). Images are content-addressed: decoded, sha256'd, deduped globally (first-seen run owns the artifact row); payload leaves become `{"$artifact": "<sha256>"}`.
4. **One `runs` table, two claude eras.** `era` select (`legacy` / `post` / `na`) + nullable post-only fields, per the report's recommendation.
5. **opencode rollups are derived by the ingester** (Σ `step_finish` cost/tokens, last−first event ts) and fill `runs` fields the ledger lacks; ledger values win when present.

Design deviations from the report's §4, found at implementation review:

- **Relation cycle broken:** §4 specified both `run_events.artifact → artifacts` and `artifacts.event → run_events`. The rel now lives only on the many side (`run_events.artifact`, `tool_calls.artifact`); `artifacts.event` is dropped. Required by schema.py's two-pass id resolution (acyclic creation order `runs → artifacts → run_events → tool_calls`) and by sha256 dedup (one artifact ↔ many events).
- **`runs.ts` is text, not date** — ledger stamps are naive local ISO; PB's date type would coerce to UTC.
- **Partial unique index on `session_id`** (`WHERE session_id != ''`) so log-less rows don't collide.
- **Artifact threshold:** write/edit content is externalized only above `ARTIFACT_TEXT_THRESHOLD = 5000` chars (module constant — flipping to "externalize all writes" is a one-line change).

Delivered (through the `schema.py` lane, never raw PATCH):

- `evals/schema.py`: `file_field` helper + the four collection specs (appended at the end of `order`).
- `evals/pb.py`: `create_multipart()` — stdlib multipart/form-data with PB's `@jsonPayload` part (file fields can't be written via JSON).
- `evals/load_harness_runs.py`: idempotent scoped ingester (`--parse-only` / `--dry-run` / `--campaign` / `--candidate`), EDB-26 discipline; hermetic unit tests in `tests/test_load_harness_runs.py` (repo `make test` lane).
- Corpus ingested + verified counts: **72 runs** (72/72 linked to a log — 24 by explicit `log_path`, 48 legacy/opencode by filename prefix, `log_path` durably backfilled), **3,045 run_events** (3,688 raw lines − 643 dropped thinking-counter rows), **1,003 tool_calls** (== the ledger's per-row `tool_names` totals, 0 mismatches), **16 artifacts** post-dedup (21 occurrences → 15 distinct screenshot sha256 + 1 oversized write; the oversized write is opencode, 5,076 chars). Era split 24 legacy / 24 post / 24 na. Idempotence proof: second `--dry-run` reported 0 create / 0 update across all four collections. Pre/post checksums of the 13 pre-existing collections: identical (EDB-11 live proof).
- One defect the idempotence gate caught and killed before landing: PB `json` fields coerce string input by a first-byte rule (a string whose untrimmed first byte can start a JSON value, and that parses, is stored PARSED — proven live: `'7853\n'` came back int while `'     266'` stayed a string), so string-JSON tool outputs (todowrite, Bash JSON prints — 91 rows) diffed as "changed" forever until the loader learned to mirror the rule at body-build time. Recorded as a gotcha in `evals/PROCEDURES.md`.

All three gaps in this issue's body are addressed: durable retention (PB, tracked `data.db` + `storage/`), row↔log linkage (`session_id` + backfilled `log_path`), and the normalized cross-vendor event schema.
