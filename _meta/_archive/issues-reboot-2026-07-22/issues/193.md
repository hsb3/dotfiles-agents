_Follow-up to the **#191** PARK ruling: functionform-asmbl is kept as the product-surface seed, but these 3 concepts are worth porting into dotfiles-agents. Low priority; captured so they aren't lost. Source is parked (reachable), not archived._

1. **GitHub-sourcing + `sync_status` (highest value)** — `apps/api/services/github.py` + `routers/github_sourcing.py`: a working reference impl of the unbuilt externals-freshness feature. **Already routed to #36 / #122** (see comment there). This item = "when building #36/#122, adapt that code."
2. **Assembly/component composition schema** — ordered `(primitive, position, transform, condition, version_pin)` + inherited `parent_assembly_id` (`apps/api/models/assembly.py`, `resolver.py`). Today dotfiles-agents bundles are flat id lists. Adopt only *if* bundles ever need ordered / parameterized / version-pinned composition — not needed yet, but this is the proven model when it is.
3. **Build-time parameterization** — `{{placeholder}}` variables (global + per-assembly override, `interpolator.py`) and a per-primitive `design_spec` rationale field. dotfiles-agents has no build-time var layer and pushes all rationale to ADRs. Evaluate if/when a bundle needs per-target parameterization.

Not scheduled into a wave — pull items as their host feature (#36/#122 for item 1) comes up.
