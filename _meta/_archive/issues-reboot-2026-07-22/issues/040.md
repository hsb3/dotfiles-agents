## Problem

The repo meta-structure standard audits everything around `docs/` but nothing inside it. The
checklist's only docs row is ROOT-08, `path-exists: docs/`
(`primitives-core/skills/repo-meta-structure/references/checklist.md:77`) — an empty `docs/`
directory passes. There is no DOCS row family, no ADR-directory requirement, and no
canonical-page requirement, even though:

- The standard itself leans on decisions it can't point at: checklist rows cite "the
  skills-over-commands decision" (CLAUDE-07) and "the hooks-as-script-plus-config decision"
  (HOOK-01 note), but this repo has no `docs/decisions/` to hold them —
  `docs/` today is `CHARTER.md`, `images/`, `sops/` only. This repo would gap against the
  very rows it should define.
- The best worked example, `hsb3/ra-platform`, carries the shape the standard should name:
  `docs/README.md` (orientation + docs-vs-`_meta/` boundary), `docs/decisions/` with
  `README.md` (append-only convention + index) and `0000-template.md` plus 29 sequential
  ADRs. It is a reference point, not necessarily the ultimate standard — the required set is
  an open decision below.
- Conversely ra-platform has no `docs/CHARTER.md` while this repo does (with the precedence
  line "if anything anywhere disagrees with this page, this page wins",
  `docs/CHARTER.md:9`) — neither exemplar passes the union today, which is exactly why the
  minimum needs to be written down as rows, not inferred from examples.

Separately, the standard's enforcement skills never reached the installed plugin: the roster
assigns `repo-meta-structure`, `repo-compliance-audit`, `mise-en-place-scaffold`, and
`memory-taxonomy` to `plugins: [project-workflow]` (`primitives-core.yaml`) and the built
target carries them (`targets/claude-code/plugins/project-workflow/skills/`), but
`plugins.yaml` still says `version: "0.1.0"` — the same version as the installed cache
(`~/.claude/plugins/cache/dotfiles-agents/project-workflow/0.1.0/`), which predates the
standards work and contains only 9 skills. Without a version bump the plugin manager sees no
update, so the audit/scaffold skills are invisible on the machines that need them.
