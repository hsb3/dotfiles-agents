## What it is

The code desk's charter is "focus on the most immediate next release," but no skill covers release mechanics. This skill drives:

- Versioning + changelog discipline (bump rules, honest release notes)
- Milestone convergence: what blocks the release; gate labels over issue counts
- Publish/release flow: tag → release → any publish workflow the repo defines (e.g. a dev→main publish workflow), never hand-rebuilding a published branch
- Release verification: install/smoke proof from the published artifact, not the working tree

## Constraints

- Identity-neutral; repo specifics come from repo config/docs, not hardcoded
- Tool-agnostic where possible (gh CLI baseline)

## Acceptance criteria

- Ships as a `code-desk` bundle member; roster `origin: authored`
- Drives a real release on at least one repo as proof (dotfiles-agents' own publish flow is a candidate)
- Neutrality lint + `make ci` green
