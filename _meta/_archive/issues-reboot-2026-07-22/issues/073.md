## What happened

Standing up a board for `mhi-raptorxai/raptorxai-infra` (org project, 2026-07-03), all three board scripts in `github-project-board/scripts/` failed on first contact:

1. **`Int!` variable passed as string.** The shared `graphql()` helper passes every variable with `gh api graphql -f`, but `PROJECT_ID_Q` declares `$n:Int!`. `-f` sends the value as a JSON string, so every invocation dies with `Variable $n of type Int! was provided invalid value`. The scripts cannot work against any project as shipped. Fix: use `-F` for the int variable (careful: only for the typed-int variable — blanket `-F`-for-digit-values breaks `String!` args like all-numeric single-select option ids, which really occur; Impact option ids on our board were all-digits).

2. **Changeset header row is required but undocumented.** `board-apply.py` parses the TSV with `csv.DictReader`, so a file matching the documented contract ("TSV diff, one row per cell: `issue<TAB>field<TAB>value`") parses to zero rows and reports `0 changed · 0 unchanged` — success-shaped output for a total no-op. Fix: document the `issue\tfield\tvalue` header in §9, and/or make the parser tolerate headerless files, and/or exit non-zero when 0 rows parse.

3. Minor: §9's example invocations omit `--owner-type org`; the default is `user` and the error when wrong ("project not found" only after the Int fix) doesn't hint at it.

## Repro

`python3 scripts/board-export.py -o <any> -n <any>` → the Int! error, before auth or owner-type even matter.

Observed on plugin cache 0.2.1. Patched locally (copy in job tmp) with `-F` only for `n` + a header row; the full loop then worked end to end (export → 73-row changeset → apply → idempotent re-run).
