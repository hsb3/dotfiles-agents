## Body

> **Origin:** Henry ("this repo needs some test/qa procedures"), 2026-06-29. Add a correctness layer on top of the existing drift guards so render/transform bugs are caught, not just inconsistencies.

## Problem

The only automated checks are two **drift guards** run by `make ci` (`Makefile:21`): `check_roster.py` (roster matches disk) and `translate.py --check` (committed `targets/` equals a fresh rebuild). They prove **consistency**, not **correctness** -- a bug in a renderer emits wrong-but-consistent output that passes `make ci` clean, because the guard only diffs the rebuild against the committed copy (`translate.py:594`).

Concretely uncovered today: the pure render/transform/parse functions in `scripts/translate.py` (the `mcp_to_*` renderers `:242/:258/:275`, `transform_agent_opencode` `:189`, the five stdlib parsers `:54/:80/:107/:122/:143`) have zero unit tests; nothing validates a source primitive's content (a skill's `SKILL.md` frontmatter, an mcp spec's required fields per transport); nothing checks a generated artifact against its target's real schema (CMA `name`+`model`, opencode `mcp` shape, `marketplace.json` keys); there is no determinism assertion and no secret-hygiene gate; and there is no test infra at all (`tests/`, `make test`, framework, CI lane). The suite is intentionally **zero-install** (`translate.py:14`), so any solution must stay stdlib-only in CI.

## Deliverables

- A -- test harness (`tests/`, `make test`, CI step) + unit tests for the pure functions: the three `mcp_to_*` renderers (stdio AND http), the transforms (`transform_agent_opencode`, `agent_system`, `skill_display_title`), the five parsers (real-file round-trip + edge cases), `_list`, `sha256_path`. Fixtures live under `tests/`, never `primitives-core/`.
- B -- `scripts/validate_primitives.py` + `make validate`: content validation the drift guards skip (skill/agent frontmatter; mcp spec `transport`+`command`/`url`; `${VAR}` placeholders not literals; `origin`/`targets`/`summary` roster cross-checks). Folded into `make ci`.
- C -- `tests/test_targets.py`: generated-artifact schema checks (CMA `name`+`model`+`system`; `*/mcp/*.json` shape; `*.upload.json`; `marketplace.json`/`plugin.json` keys) + invariants (build-twice determinism; secret-hygiene scan of `targets/`).
- D -- (DEFERRED, opt-in `make smoke`, not in required CI) loadability against the real tools: CMA payloads vs the pinned `BetaManagedAgentsCreateAgentParams`; opencode/CC config-parse smoke that skips when the tool is absent.

Full build detail, file scope, and landing order: `_meta/plans/test-qa-procedures/plan.md`.

## Acceptance criteria

- [ ] `make test` runs green with **zero `pip install`**; CI runs it.
- [ ] Each `mcp_to_*` renderer has a stdio AND an http assertion; `transform_agent_opencode` is asserted to preserve a multi-line `description` byte-for-byte.
- [ ] A deliberately mutated expectation makes the suite FAIL (the tests can actually catch a regression).
- [ ] `validate_primitives.py` exits non-zero on a broken fixture (skill missing `description`; mcp spec missing `transport`) and zero on the real tree; it is part of `make ci`.
- [ ] The determinism test builds twice and asserts byte-identical output; the secret scan passes on current `targets/` and FAILS on a fixture carrying a literal token.
- [ ] Every `targets/claude-agents/agents/*.json` is asserted to carry `name`+`model`.

## Dependencies & gates

- `make ci` (aggregate, required): FIRES -- this adds `test`+`validate` lanes into it.
- Roster drift guard: does NOT fire, PROVIDED fixtures live under `tests/` not `primitives-core/` (else `check_roster.py:55` flags them as orphans).
- Targets drift guard: does NOT fire -- no `primitives-core/`/roster/config edits; tests only READ `targets/`.
- `actionlint`/`yamllint`: FIRES -- editing `.github/workflows/ci.yml` to add the lane.
- Naming taxonomy: does NOT fire -- adds only `scripts/` + `tests/`, no primitive/plugin.
- Owner decisions RESOLVED (2026-06-29): framework = stdlib `unittest` (zero-install); separate `make test` + `make validate`, both in `make ci`; validation as a `scripts/` guard, unit tests in `tests/`; **defer D** to a follow-up; no new gate label. See the plan's "Owner decisions (RESOLVED)".

## Out of scope

- Real end-to-end loading inside Claude Code / opencode / the CMA API (that is D, deferred and opt-in).
- The skill/plugin clone-at-build externals path (unrelated, separately tracked).
- Reformatting or refactoring `translate.py` beyond what testability requires.
- Any new runtime dependency in the required CI lane (the suite stays zero-install).
