> **Tracking:** #6, the residual after the Phase 3 MVP translation service shipped (#17). Build the two adapters the MVP deliberately deferred: the Claude managed-agents (CMA) renderer and the mcp renderer.

## Problem

The translation service shipped as an MVP (#17): `scripts/translate.py` renders **skills** (native copy) and **agents** (opencode transform) and assembles the **Claude Code marketplace**, gated by `make ci`. Two capability cells in `primitives-core-translation-config.yaml` are configured but **not implemented** — they are recorded as skips, not rendered:

- **claude-agents (CMA)** — `scripts/translate.py:290-301` records every claude-agents target as `{"capability": "render", "reason": "claude-agents (CMA) adapter deferred (post-MVP)", "skipped": true}`. So `targets/claude-agents/` is empty (only `.gitkeep`) and the results lock carries 71 deferred skips. The adapters `cma_skill_upload` / `cma_agent_create` named at `primitives-core-translation-config.yaml:43,48` don't exist. The CMA contract is already pinned (CANON "Resolved — managed-agents (CMA) contract": `POST /v1/skills` multipart with `SKILL.md` at root; `POST /v1/agents` with `BetaManagedAgentsCreateAgentParams`).
- **mcp render** — `primitives-core-translation-config.yaml:50-53` configures `mcp_to_claude` / `mcp_to_opencode` / `mcp_to_cma`, but `primitives-core/mcp/` is **empty** (only `.gitkeep`), and the roster has **zero** `type: mcp` entries. There is nothing to render and nothing to test the renderer against — mcp render is blocked on a first mcp primitive existing.

This is the deferred half of #6; the MVP half (skills/agents/CC marketplace + drift guard) is done and closed via #17.

## Deliverables

- **A — CMA adapter** in `scripts/translate.py` (replaces the deferred-skip block at `:290-301`). Emit static, deterministic artifacts under `targets/claude-agents/`:
  - per skill targeting claude-agents: a build-sheet/manifest describing the `POST /v1/skills` multipart upload (the skill folder is uploaded as-is; `name`/`description` extracted from `SKILL.md`).
  - per agent: a `BetaManagedAgentsCreateAgentParams` payload JSON (`name`, `model`, `system` = agent body, `tools[]`, `skills[]` refs, `mcp_servers[]`).
  - record real (non-skip) results in `primitives-core-translation-results.json`; extend `make build-check`/CI to guard `targets/claude-agents/`.
- **B — mcp render adapter** (`mcp_to_claude` / `mcp_to_opencode` / `mcp_to_cma` in `scripts/translate.py`) — implement against the neutral `primitives-core/mcp/<name>.json` spec, **gated on a first mcp primitive existing** (see Dependencies). Until then, the cells stay `render`-configured but unexercised.

## Acceptance criteria

- [ ] `targets/claude-agents/` is non-empty after `make build`: contains a CMA payload/manifest for every roster entry whose `targets` includes `claude-agents` (71 today).
- [ ] `primitives-core-translation-results.json` shows `claude-agents` entries with `"skipped": false` and a `destination` + `sha256` (grep for `"claude-agents (CMA) adapter deferred"` returns zero hits).
- [ ] Each generated agent payload is valid JSON and carries the required `BetaManagedAgentsCreateAgentParams` fields `name` + `model` (verifiable: `python3 -c` loads each and asserts the keys).
- [ ] Build is deterministic — `make build` twice produces byte-identical `targets/claude-agents/` + lock (the existing run-twice check extended to the new target).
- [ ] `make ci` (drift guard) green: `translate.py --check` covers `targets/claude-agents/`.
- [ ] **B (mcp):** when a `type: mcp` primitive is added to the roster, `make build` renders it to each target without a code change to the adapters; `make ci` stays green. (If no mcp primitive is added in this issue, B is split to a follow-up — see Out of scope.)

## Dependencies & gates

- **Blocks on:** Deliverable B blocks on a first `type: mcp` primitive existing in `primitives-core/mcp/` + the roster — there is none today, so B cannot be exercised or tested until one lands. A is unblocked (real inputs exist).
- **Gates that fire:** `make ci` (the roster + targets drift guards) — always; **targets drift guard** (`make build-check`, fix with `make build`) — this changes generated `targets/` output, so the lock must be regenerated in the same PR; `yamllint`/`actionlint` if the config or CI workflow changes.
- **Gates that do NOT fire:** roster↔disk (`make check`) only matters if primitives change — A/B add no primitives (B's mcp primitive, if added, would trigger it); no DB / infra / API-codegen gates in this repo.
- **Contract to keep in sync:** the CMA contract in CANON "Resolved — managed-agents (CMA) contract" — if the adapter deviates from the pinned `POST /v1/skills` / `POST /v1/agents` shapes, amend that note in the same change.

## Out of scope

- **Live API calls / uploading** to the managed-agents API — the adapter emits **static payloads/build-sheets** only; actually POSTing them is a deploy-time concern (dotfiles-bootstrap), not the translation build.
- Model-id mapping for CMA agent payloads beyond carrying the agent's stated tier (the opencode transform already omits model; same simplification applies unless a mapping is decided).
- If no mcp primitive is created here, **Deliverable B becomes a tracked follow-up** ("render the first mcp primitive") rather than blocking A from closing #6's CMA half.
