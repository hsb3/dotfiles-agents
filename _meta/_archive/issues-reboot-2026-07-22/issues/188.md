## Problem
`primitives-core/` is defined as "the single source copy of every **primitive**" (flow node `primitive-bodies`). A **bundle** is an *assembly/composition config* (which primitives group into a plugin), not a primitive itself. Nesting `primitives-core/bundles/` under the primitives source blurs that line — Henry flagged it directly.

## Blast radius (flow-DAG-touching)
`primitives-core/bundles/{code-desk,diagrams,exec-desk,foreman-kit,obsidian-toolkit}` is read by: `scripts/gen_marketplace.py`, `tests/test_gen_marketplace.py`, `docs/CONTRIBUTING.md`, `primitives-core/README.md`, `evals/ingest.py`, `scripts/check_identity.py`, plus the `primitive-bodies` flow node note. A move must update all of them + add a `bundles/` (or `assemblies/`) top-level flow node and re-run `make flow`.

## Options
- **A (recommended): top-level `bundles/`** with its own flow node (layer `roster`). Cleanest separation: primitives = parts, bundles = assembly configs. One sequenced wave (shares flow.yaml + the generator with NOTE-d).
- **B: rename in place** to `primitives-core/_bundles/` or similar — cheaper, keeps the coupling, weaker signal.
- **C: leave it** — the coupling is tolerable; close as wontfix.

## Recommendation
A. It matches the mental model the repo already documents (roster + dist lanes) and the functionform-asmbl "parts vs assemblies" framing. Needs Henry's sign-off (major IA change).
