Standard

Adopt the minimum task-definition standard (as backlog decision-7)?

Many cards are stubs like "Migrated from GH #163." with nothing else — and those source issues are now closed, so the substance is effectively orphaned. A standard makes this binding on every future session, not just this cleanup. The five rules:

  • Cold-readable description — what, why now, in current-architecture terms; never a bare "Migrated from GH #N".
  • Acceptance criteria on every task, each independently verifiable (a command, artifact, or grep — never "works well").
  • References that resolve — cited paths and decisions must exist in the current tree.
  • Status truth — shipped work is marked Done with notes citing the PR/commit, in the same PR that ships it.
  • Decision tasks name the question, the options, and that you rule.
Recommendation: adopt as decision-7 and encode a task template in the repo so sessions follow it by default.
Approach

How to "clear and repopulate": rewrite in place, or wipe and renumber?

Task IDs are load-bearing provenance: decisions, ADRs, the new vendoring-rule doc, commit messages, and PR bodies all cite task numbers (task-10, task-11, …). A full wipe with fresh numbering permanently breaks that web. Rewriting in place still gets you a clean board: Done and dead cards archive out of view, and every surviving card is rewritten to the new standard in one hand-edited PR (hand-edited because the backlog CLI can silently rewrite sibling task files). Where the architecture pivot changed a task's framing entirely, we archive the old card and open a fresh one citing its ancestor.

Recommendation: rewrite in place with stable IDs; renumber only cards whose framing genuinely changed.
